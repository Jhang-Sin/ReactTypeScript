=============《HIS 日期處理鐵律》=================

🏁 最終總結（請記住）
HIS 是「日期系統」，不是「時間軸系統」
日期 ≠ 時間
字串 > Date
頁面 > 元件
Ⅰ. 日期資料的三個層級（一定要分清楚）
1️⃣ 純日期（Date Semantic）✅【HIS 主流】

代表「哪一天」
不含時間、不含時區
用於：
掛號日期
排班日期
門診日期

唯一合法格式：YYYY-MM-DD
📌 範例："2026-11-16"
👉 HIS 所有核心資料、比對、JOIN、filter，全部使用這一層
2️⃣ 時間點（Time Point Semantic）⚠️【限縮使用】
代表「某一刻」

會受到：
時區（UTC / GMT+8）
DST
瀏覽器實作影響 
範例：
new Date()
new Date("2026-11-16T08:00:00")
❗ 禁止用途：
-當掛號日期
-當排班日期
-當查詢條件

✅ 允許用途（僅限）：
-計算今天 + N 天
-判斷是否過期
-倒數天數

3️⃣ 顯示用日期（Display Semantic）🖥
只存在於畫面
可轉為：
-中文
-民國
-上午 / 下午 / 晚上
📌 範例：
 2026/11/16
2026年11月16日
星期一
👉 顯示層絕不可反寫回資料層

Ⅱ. HIS 的「鐵律」清單（請照貼在牆上）
🧱 鐵律 1：禁止 new Date("YYYY-MM-DD")
// ❌ 絕對禁止
new Date("2026-11-16");
原因：
JS 規格會當成 UTC 00:00
轉本地時區可能變成 隔天

🧱 鐵律 2：日期主資料一律是字串
// ✅ 正確
this.selectedDate = "2026-11-16";
JSON
Vue data
filter 條件
👉 全部是字

🧱 鐵律 3：日期比對只比字串
// ✅ 正確
String(a) === String(b)
// ❌ 錯誤
new Date(a).getTime() === new Date(b).getTime();

🧱 鐵律 4：行事曆元件只能回傳「日期字串」
// ✅ 行事曆 → 頁面
onCellClick(day) {
page.onDateSelected(day.key); // YYYY-MM-DD
}

❌ 不允許：
this.selectedDate = day.date; // Date 物件

🧱 鐵律 5：事件流程由頁面決定，不由元件決定
行事曆元件責任：點擊 → 回傳資料
頁面責任：接資料 → 決定要不要 loadDate()

Ⅲ. utilities.js 使用規範
✅ 可以存在的工具

HIS.util = {
// 產生今天 YYYY-MM-DD
todayYMD(),


// Date → YYYY-MM-DD（僅限 new Date()）
formatDateYMD(date),


// 日期字串比較
isSameDate(a, b),


// 日期字串 + N 天
addDays(ymd, days)
}


❌ utilities.js 不可以做的事
-❌ 自動把字串轉 Date
-❌ 偷偷補時區
-❌ 模糊格式（2026/11/16、11-16-2026）


Ⅳ. reg_by_date.js 的標準流程（範本）
[事件] 使用者選日期
↓
取得 YYYY-MM-DD 字串
↓
設定 selectedDate
↓
呼叫 loadDate()
↓
用字串 filter schedule
